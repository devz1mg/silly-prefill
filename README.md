# Silly Prefill

Function-response prefill, visual prefixes and post-processing chains for **SillyTavern 1.19+ / Chat Completion**. Version **1.6.2**.

Изменения ядра SillyTavern в этот репозиторий не входят. Для ручной визуальной кнопки они не нужны.

## Установка

1. В SillyTavern откройте **Extensions → Install extension**.
2. Укажите `https://github.com/devz1mg/silly-prefill`.
3. Установите расширение и обновите страницу. После обновления файлов используйте **Ctrl+F5**.
4. Откройте панель **Silly Prefill** и заполните свой prefill. Пользовательские тексты, чаты и пресеты не поставляются.

Не включайте одновременно несколько расширений, инжектирующих один и тот же function-prefill. Перед изменениями экспортируйте настройки и сделайте резервную копию чатов.

## Function-response prefill

Расширение добавляет синтетическую пару assistant function call / tool result с началом ответа и инструкцией продолжить его. Доступны Custom assistant prefill, штатный Start Reply With, сообщение перед function call, редактируемая декларация Gemini prefill-tool и опциональный Claude bridge.

Это не гарантированный нативный assistant-prefill: модель может проигнорировать продолжение, повторить начало или вызвать функцию снова. Результат зависит от модели, API, прокси и backend Tavern.

## Визуальная кнопка ¶

У ответа персонажа откройте **`…` → `¶`** — **«Вставить префилл (только визуально)»**.

- Первое нажатие добавляет текущий prefill перед отображаемым текстом; второе убирает его.
- Источник — Custom prefill или Start Reply With с подстановкой макросов.
- Текст выводится буквально, без исполнения HTML и без Markdown-форматирования самого префикса.
- `message.mes`, текст свайпов, provider reasoning и signatures не переписываются. Кнопка не добавляет префикс в будущий контекст модели.
- Отдельная display metadata сохраняется для активного swipe и восстанавливается при загрузке чата. Правка исходного сообщения делает старую проекцию неактивной.
- Уже присутствующий в начале основного текста полный префилл повторно не добавляется.

Работает без server plugin и модификаций ядра. Использует текущие настройки на момент нажатия, а не неизвестный prefill старого запроса. Ручное нажатие сохраняет metadata чата; автоматического переписывания старых сообщений при установке нет.

## Внешние блоки / цепочки

После основного ответа можно запускать запросы через профили **Connection Manager**: добавить текст сверху/снизу, переписать ответ или сохранить скрытый результат для следующих блоков. Есть промпты, regex-условия/извлечение, prefill, шаблоны, ручной запуск, остановка, Undo и экспорт настроек.

Для видимых блоков **Chat history / История чата** определяет: передавать результат модели или оставлять в контексте оригинал. «Только оригинал» не удаляет результат из JSON/metadata чата. Явная вставка отображаемого текста в промпт блока намеренно передаёт его выбранному профилю независимо от режима истории.

Команды: `/sp-chain [block=Имя] [id]`, `/sp-chain-stop`, `/sp-chain-clear [id]`, `/sp-chain-undo [id]`.

Макросы блоков: `{{lastOriginalMessage}}`, `{{targetMessage}}`, `{{topPos}}`, `{{bottomPos}}`, `{{captureChar::N}}`, `{{captureUser::N}}`, `{{prevOutput}}`, `{{blockOutput::Имя}}`, `{{chainHistory::N}}`, `{{startWith}}`, `{{toolRequest}}`.

Запросы блоков используют ваши подключения и могут оплачиваться провайдером.

## Additional Parameters: опциональный серверный плагин

Body/header overrides для Chat Completion: общий профиль, переопределения по источнику, YAML include/exclude и макросы. Для изменения финального запроса провайдеру нужен отдельный server plugin. Для визуальной кнопки он не нужен.

1. Скопируйте каталог `server-plugin/silly-prefill-params` из репозитория в `plugins` вашей Tavern.
2. Итоговый путь: **`SillyTavern/plugins/silly-prefill-params/index.js`**. Не оставляйте промежуточный `server-plugin` внутри `plugins`.
3. В `SillyTavern/config.yaml` включите `enableServerPlugins: true`.
4. Перезапустите сервер и проверьте статус плагина в панели расширения.

Обычная установка клиентского расширения не устанавливает серверный код автоматически. Не помещайте секреты в экспортируемые профили; используйте штатное хранилище ключей Tavern.

## Совместимость и ограничения

| Функция | Условия |
|---|---|
| Ручная визуальная кнопка ¶ | Обычное ядро, без server plugin |
| Synthetic function-prefill | Зависит от tools и преобразований конкретного backend |
| AUTO / NONE / ANY | Требуют поддержки режима конечным API |
| VALIDATED / allowed function names | Полное применение требует совместимого backend/core; наличие UI не гарантирует forwarding на штатном ядре |
| Автоматический Show reply prefix in chat | Требует корреляции request IDs с сообщением; без неё расширение намеренно не угадывает принадлежность ответа. Используйте ручную кнопку ¶ |
| Полный raw-Part replay / новые Argon thinking mappings | Не добавляются установкой этого расширения |
| Additional Parameters | Требуют отдельного server plugin |

AUTO разрешает текст или вызов функции; NONE запрещает новые вызовы; ANY требует вызов и может вызвать prefill-tool повторно. VALIDATED, где поддерживается, допускает текст либо вызов с соблюдением схемы. Эти режимы не переключают канал thinking и не гарантируют следование system/prefill.

Custom function declarations могут конфликтовать с Google Search и другими built-in tools в конкретном backend. В таком случае проверьте **Declare prefill tool & description for Gemini** и возможности своей Tavern.

### Thinking и signatures

- Ручной `<think>`-шаблон, provider thought text и opaque thought signature — разные сущности.
- Расширение не обещает доступ к raw internal reasoning, отключение нативного thinking или его замену вашим шаблоном.
- Fetch signature выполняет отдельный модельный запрос, который может оплачиваться.
- Borrowed signatures, protobuf-shaped и random short tokens — **эксперимент**, не проверенные подписи провайдера и не гарантия корректного replay. Они не доказывают восстановление мыслей модели.
- Расширение не обновляет список моделей, токенизатор и контекстные лимиты ядра Tavern.

Универсальная совместимость со всеми моделями/прокси не подтверждена. Offline-тесты и изолированные UI-проверки не заменяют проверку реального endpoint.

Создайте [issue](https://github.com/devz1mg/silly-prefill/issues) с версиями Tavern/расширения, моделью, типом API и шагами воспроизведения. Удаляйте из логов ключи, Authorization/cookies, реальные signatures, continuation tokens и приватный текст чатов.
