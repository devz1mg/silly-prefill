# Silly Prefill

## 1.7.1 — авторство и явный визуальный Rewrite

Автор расширения: **devz1mg**. Внешний блок → **Rewrite the message** → **Chat history / История чата** → **Только визуально — в историю только оригинал**. В чате виден переписанный текст, а `message.mes`, активный текст свайпа и будущие запросы содержат оригинал. Альтернатива — **Переписать текст и историю модели**. Выбор действует со следующего запуска блока, не пересчитывает уже обработанные сообщения. Отображение хранится в metadata чата, не является удалением текста из файла. Явная вставка `{{targetMessage}}` в другой блок по-прежнему передаёт ему видимый текст.


## 1.7.0 — Argon experimental protobuf v2 и GPT

- **Thought signature mode → `argon-exp-proto-v2`**: отдельная экспериментальная 91-байтовая protobuf-shaped заготовка с префиксом `ElkKVwFpFH0T…`, совместимая по формату с исследованным Kuro Prefill. Старый режим `protobuf` и fallback `real_or_protobuf` остаются прежними. Это не подпись Google и не восстановленная думалка; принятие Argon/прокси не проверено.
- **Enable GPT function-prefill**: synthetic function call / tool result для GPT, Astra, Sol, Luna и o1/o3/o4. Включено по умолчанию; Gemini AUTO/declaration не меняются. Для GPT не отправляются Gemini `signature` / `extra_content.google` и лишнее `name` у tool-result.
- **Attach GPT encrypted reasoning (experimental)** — выключено по умолчанию. При включении AUTO берёт только подходящий custom или сохранённый Fernet-shaped токен с совпадающей model/source/transport; без токена ничего не синтезирует. Перенос токена между ответами не гарантирует валидное состояние.
- **GPT Fernet-shaped token** — отдельный экспериментальный режим: 313-байтовое обрамление с timestamp и случайными байтами, **без AES/HMAC и без подписи провайдера**. Нужен отдельный checkbox Attach GPT encrypted reasoning. Поле `reasoning_details` с `openai-responses-v1` не переключает `/chat/completions` на Responses API.
- Кнопки **Generate argon-exp-proto-v2** и **Generate GPT token** работают локально, заполняют Custom и не меняют выбранный режим или checkbox прикрепления. Генерация GPT-токена не приводит к его отправке Gemini.
- **Declare prefill tool for GPT** и **Normalize GPT sampling** — отдельные опции, обе выключены по умолчанию. Нормализация снимает sampling/penalty-поля только у выбранных GPT reasoning-семейств при явно активном effort; `auto`, отсутствующее значение, `none` и `min` не переписываются. Это опциональная политика совместимости, не универсальный контракт прокси.
- GPT Fetch отправляет отдельный plain-output запрос без tools; может оплачиваться и не гарантирует получение encrypted reasoning. Защита от запоздалых ответов Fetch сохранена.
- Function-prefill внешних блоков также различает GPT и Gemini: GPT не получает Google-подписи; режим Argon v2 применим к Gemini-блокам. Опциональная нормализация sampling относится к основному запросу и Fetch, не переопределяет sampling профиля цепочки.
- Цепочки, Additional Parameters, защита provider reasoning и визуальная кнопка `¶` сохранены. Ядро Tavern не обновляется, модели/пресеты/чаты и активный signature mode не переключаются. На обычном ядре для ручного отображения начала используйте `¶`; ограничения автоматического Show reply prefix остаются.
- После обновления клиентских файлов достаточно **Ctrl+F5**. Плагин сервера не менялся. Платные provider-запросы при разработке не выполнялись.


Расширение SillyTavern (1.19+, Chat Completion).

## 1. Prefill через function response
Префилл ассистента заворачивается в синтетический вызов tool + `tool`-ответ, чтобы Gemini (и, опционально, нативный Claude) продолжал текст с него.

### Новое в 1.6.2 — ручной визуальный префилл на старом ядре
- В меню действий `…` у ответа персонажа появилась кнопка `¶` — **«Вставить префилл (только визуально)»**. Она добавляет текущий custom-prefill или Start Reply With в начало отображения ответа. Повторное нажатие убирает его.
- Кнопка работает без core request IDs и не требует наших обновлений Tavern. Основной `message.mes`, swipes, provider reasoning, signatures и отправляемый контекст не переписываются. Сохраняется только отдельная metadata отображения `extra.sp_visual_prefill` для активного swipe; после reload она применяется снова. Правка исходного текста делает старую проекцию неактивной. Это ручная косметическая функция, не возобновление автоматического Show reply prefix.
- Префилл берётся из текущих настроек на момент нажатия и выводится буквально, без исполнения HTML. Кнопка не восстанавливает неизвестный префилл старого запроса и не расшифровывает thinking. Если префилл уже есть в начале основного текста, повторно он не вставляется.

### Исправление 1.6.1 — пропажа ручного think-блока после streaming
- Исправлен destructive extraction: при пустом provider reasoning и присутствующей opaque signature блок `<think>…</think>` больше не вырезается без сохранения. В этом случае ручной префикс и продолженный моделью текст остаются в основном тексте сообщения, а не подменяют подписанный provider reasoning. Swipes получают тот же сохранённый текст; signature/raw Parts не меняются. Это точечное исправление MESSAGE_RECEIVED, не новый API-доступ к внутренней думалке.

### Новое в 1.6.0 — Argon compatibility и сохранность reasoning
- Добавлены **VALIDATED** и optional **Allowed function names** (одно точное имя на строку) для ANY/VALIDATED. AUTO остаётся default. Имена не переименовываются; неизвестное/невалидное имя блокирует запрос. Explicit named tool choice имеет приоритет. Main и function-prefill chain используют одинаковые controls; Fetch остаётся отдельным AUTO probe без whitelist. В chain доступны только функции, объявленные самим блоком.
- Исправлены перезапись provider reasoning ручным think-prefill, сброс pending фоновым Quiet, принадлежность reply/request/swipe, provenance cache и гонки Fetch/Clear/ручных правок. Полученный reasoning/signature не заменяются ручным блоком. Legacy cache без model/source provenance не используется автоматически; экспериментальные ручные controls сохранены и не объявляются валидным provider state.
- **Требуется core update из того же комплекта**, не только новое расширение: ядро добавляет request IDs, сохраняет полученные native Parts и compatible metadata через history/swipes, выбирает parser по фактическому transport и передаёт Argon thinking controls через OpenAI/Custom. На старом core injection остаётся возможной, но show-prefill без подтверждённого request ID намеренно не угадывает принадлежность ответа.
- Raw replay допускается только для неизменённого captured content и совпадающего model/source/endpoint. **Show reply prefix**, если изменил `message.mes`, оставляет исходное provider state сохранённым, но отключает его replay. Нельзя одновременно заявлять изменённый context неизменённым подписанным ответом. Обычные ручные правки и context-changing blocks также могут отключить replay. Изменение display/context semantics не внедрялось.
- Signed/opaque Parts сохраняются в доступном исходном порядке; логические границы поверх произвольной stream fragmentation не восстанавливаются. Cloud partialArgs, смешанные built-in/custom tools, Interactions и long decode не добавлены. Поддержка signatures не означает доступ к raw CoT.
- Обновление не меняет активные модели, presets, connection profiles, чаты и бюджеты. После core update нужен перезапуск ST и Ctrl+F5; companion plugin не менялся. Реальное принятие платным Google API не проверялось — использованы offline fixtures и локальный HTTP/SSE upstream.

### Новое в 1.5.0 — External blocks: результат или оригинал в истории
- В каждом видимом блоке (сверху, снизу, переписать пост) появился селектор **Chat history / История чата**: **В историю — результат** или **В историю — только оригинал**. Он заменяет прежний checkbox Visible to the main model и распространяется также на Rewrite.
- **Результат**: переписанный пост заменяет текст в контексте модели, добавленный блок включается в него. **Только оригинал**: в чате виден результат обработки, но `message.mes` и будущие запросы содержат исходный пост без результата этого блока. Видимый результат сохраняется отдельно в `extra.display_text`; это не удаление результата из файла чата или метаданных.
- Первоначальный текст теперь не перезаписывается Rewrite: оригинал и активная редакция хранятся отдельно. Undo возвращает предыдущую редакцию вместе с её режимом истории; Remove blocks возвращает оригинал для новых сообщений этого формата. Оригинал сохраняется и при нескольких переписываниях.
- Display-only результат фиксируется после обработчиков `MESSAGE_UPDATED`: штатный Translate при выключенном автопереводе больше не удаляет его перед показом/сохранением. Правка ограничена расширением, код переводчика и ядра не менялся.
- Основная история модели, **+ Chat history** в блоках и `{{chainHistory::N}}` учитывают выбранную проекцию. `{{lastOriginalMessage}}` и capture-макросы по-прежнему дают оригинал; `{{targetMessage}}` даёт видимый пост, включая переписывание и display-only блоки. Явная вставка этого макроса намеренно передаёт видимый текст помощнику независимо от history mode.
- Выбор сохраняется по каждому блоку, дублируется и экспортируется вместе с ним. Для новых блоков default — только оригинал. У старых блоков сохраняется прежнее поведение: Rewrite → результат, сверху/снизу → старый includeInContext.
- Выбор применяется при следующем запуске блока. Уже обработанные сообщения автоматически не пересчитываются; для них нужен новый запуск/Undo. Старые сообщения не мигрируются и не переписываются при обновлении. Если прежняя версия уже затёрла первоначальный текст, новый режим не может гарантированно восстановить его задним числом.
- Hidden-блоки остаются скрытыми и автоматически в историю не попадают. Режимы разных блоков независимы: «только оригинал» у одного блока не запрещает добавление результата другого. Остальные находки полного аудита не объявляются исправленными.

### Добавлено в 1.4.0 — Declare prefill tool и function calling mode
- Переключатель в **Connection & model support** переименован в **Declare prefill tool & description for Gemini**. Он добавляет объявление функции целиком: имя, description и parameter schema. Поле **Prefill tool description** отдельно редактирует текст инструкции.
- Добавлен сохраняемый селектор **Gemini function calling mode**: **AUTO** (по умолчанию), **NONE**, **ANY**. В старых настройках, где режима ещё нет, выбирается AUTO; остальные поля не сбрасываются.
- Для нативного Gemini Tavern переводит `tool_choice: auto / none / required` в `toolConfig.functionCallingConfig.mode: AUTO / NONE / ANY`. На OpenAI-compatible transport уходит `tool_choice`. Настройка применяется только при объявлении Gemini prefill-tool, включая function-prefill блоков цепочки; при выключении declaration селектор неактивен, сохранённый выбор остаётся.
- Селектор заменяет строковый `tool_choice`, включая штатный AUTO Tavern, поэтому NONE/ANY работают и при наличии других функций. Выбор касается **всех объявленных функций**, а не только prefill-tool. Явно принудительно выбранная по имени функция из другой интеграции сохраняет приоритет. Claude и не-Gemini блоки этим селектором не меняются.
- **AUTO** разрешает модели выбрать текст или вызов функции с учётом доступных declarations. Это не отмена системных инструкций и не гарантия заданного маршрута генерации. **NONE** запрещает новые вызовы, сохраняя synthetic-пару в истории. **ANY** требует новый вызов функции: модель может повторно вызвать фиктивный prefill-tool вместо продолжения ответа; это экспериментальный вариант, не рекомендуемый для обычного продолжения.
- **Fetch real signature** остаётся отдельным диагностическим запросом с AUTO независимо от селектора и выключателя declaration: ему нужны собственные tools для проверки signature. Additional Parameters по-прежнему применяются позднее и могут явно переопределить `toolConfig` / `tool_choice`.
- Объявление функции по-прежнему может отключить встроенный Google Search в текущем backend Tavern. Изменения касаются расширения; серверный плагин и ядро не менялись. Это не исправление остальных ошибок полного аудита.

### Добавлено в 1.3.0 — совместимость с форматами Kuro Prefill
- Распознаются Gemini signatures из `responseContent.parts`, raw `candidates[0].content.parts`, вложенных `functionCall`, top-level `thoughtSignatures`, OpenAI-compatible aliases и OpenRouter encrypted reasoning. Пустой/короткий alias не маскирует следующее пригодное поле. Это распознавание opaque token, не извлечение скрытой думалки и не проверка подлинности подписи.
- Синтетические IDs `sp_` / `kp_` и dummy names `silly_prefill` / `kuro_prefill` не считаются источником настоящей signature. Уже присутствующая synthetic-пара Kuro не инжектируется второй раз. Одновременную установку двух расширений всё равно использовать не рекомендуется.
- Fetch real signature учитывает OpenAI proxy transport так же, как основной запрос, использует своё Gemini/Claude description и сохраняет штатный выбор модели/Custom fields. Профиль Additional Parameters выбирается по фактическому source payload; после native→OpenAI переключения параметры пересобираются для финального source.
- Кэш обновляется также на `CHARACTER_MESSAGE_RENDERED`. Token и имя модели берутся из одного сообщения; render другого сообщения не заимствует старую signature и не приписывает её Claude.
- Tool schema дополнена необязательным boolean `pre_function_message`; основной synthetic call сообщает, присутствует ли pre-function message.
- **Generate short token (experimental)**: ручная локальная генерация 85-byte random token в формате эксперимента Kuro. Это **не provider-signed signature**, не гарантированный обход проверки и не способ получить reasoning. Кнопка меняет только Custom / fetched signature, **не переключает выбранный mode** и не отправляет API-запрос. При отсутствии secure crypto сообщает ошибку без замены старого значения. Автоматического short-token fallback нет.
- Наши dedup, chain, Additional Parameters и Claude bridge сохранены. Сохранённые настройки Kuro автоматически не импортируются; существующие настройки Silly Prefill не заменяются.

**Исторические границы 1.3:** перенос был выборочным. Pending-prefix/reasoning restoration исправлены отдельно в 1.6; прочие schema-mapping и chain/server находки не считаются автоматически закрытыми. Криптографическая пригодность borrowed/synthetic signatures не гарантируется.

### Добавлено ранее в 1.2.0
- **Gemini tool description** (прежнее название переключателя): редактируемая инструкция, объясняющая, что результат инструмента — уже написанное начало ответа. Есть выключатель, сброс и полноэкранный редактор. По умолчанию включено. В 1.2–1.3 для единственного фиктивного инструмента использовался `tool_choice: none`; с 1.4 режим выбирается селектором и по умолчанию равен AUTO.
- Объявление функции может отключить встроенный Google Search в текущем backend Tavern. При несовместимом прокси или необходимости поиска выключите **Declare prefill tool & description for Gemini**.
- **Не дублировать prefill** (Prefill): перед восстановлением отправленного начала проверяет и реплай, и `extra.reasoning`, включая уже разобранные Reasoning Prefix / Suffix. Сравнение учитывает различия в пробелах/переносах, но не перефразирование. По умолчанию включено; работает вместе с Show reply prefix in chat.
- Проверка выполняется при получении полного ответа / завершении streaming, а не на каждом токене. Используется точный отправленный prefill после подстановки макросов: Start Reply With либо Custom assistant prefill. Если думалка уже есть, а текстовое окончание prefill ещё нет, восстанавливается только недостающая текстовая часть.
- Текст, написанный моделью, не вырезается: функция предотвращает дополнительную вставку расширением, не удаляет самостоятельно повторённые моделью фрагменты и не меняет старые сообщения. Quiet / Continue / Impersonate по-прежнему не получают восстановление начала.

## 2. Additional Parameters для всех источников
В стандартном ST кнопка «Additional Parameters» есть только у Custom (OpenAI-compatible). Здесь это работает для любого источника Chat Completion.

- Профиль **Global** применяется ко всем источникам, профиль конкретного источника (`makersuite`, `claude`, `openrouter`, …) мержится поверх него.
- **Include Body**: YAML-объект, вложенные объекты мержатся глубоко (`generationConfig.thinkingConfig` и т.п.).
- **Exclude Body**: YAML-список ключей; поддерживаются пути через точку (`generationConfig.topK`).
- **Include Headers**: YAML-объект. `Authorization`, `x-api-key`, `x-goog-api-key`, `Host`, `Content-Length` и подобные переопределить нельзя.
- Макросы (`{{char}}` и т.д.) поддерживаются.
- Параметры применяются к **финальному** запросу провайдеру, то есть уже после того, как ST перевёл его в формат Gemini/Claude/…

### Установка серверного плагина (обязательно для Additional Parameters)
ST собирает тело запроса провайдеру на сервере из фиксированного набора полей, поэтому без серверной части это сделать нельзя.

1. Скопируйте папку `silly-prefill-params` (внутреннюю, не `server-plugin`) так, чтобы получилось `SillyTavern/plugins/silly-prefill-params/index.js`. ST ищет плагины только на один уровень вглубь.
2. В `SillyTavern/config.yaml` поставьте `enableServerPlugins: true`.
3. Перезапустите ST. В настройках расширения должно появиться «Server plugin: installed».

Плагин никуда не отправляет данные и не читает ключи API. Он забирает поле `sp_additional_params` из `/api/backends/chat-completions/generate` и меняет только первый исходящий JSON POST в рамках этого запроса (это запрос к провайдеру).

## 3. Внешние блоки (цепочка)
После ответа основной модели блоки по очереди отправляют запросы через профили Connection Manager.

Режимы: **сверху**, **снизу**, **переписать сообщение**, **скрытый** (только для макросов следующих блоков).
У каждого блока свой «пресет»: список промптов с ролями (system/user/assistant + вставка истории чата), prefill (assistant или function response), Start With, max tokens, температура, условие запуска (regex), извлечение из ответа (regex), шаблон-обёртка.
У видимых блоков (сверху/снизу/переписать) настройка **Chat history / История чата** определяет, войдёт ли результат в будущие запросы или будет только отображаться (`extra.display_text`) при сохранении оригинала в `mes`.
Блок можно отдать основной модели как tool (function calling).

Макросы внутри блоков: `{{lastOriginalMessage}}`, `{{targetMessage}}`, `{{topPos}}`, `{{bottomPos}}`, `{{captureChar::N}}`, `{{captureUser::N}}`, `{{prevOutput}}`, `{{blockOutput::Имя}}`, `{{chainHistory::N}}`, `{{startWith}}`, `{{toolRequest}}`.
Глобально (в основном пресете тоже): `{{lastOriginalMessage}}`, `{{topPos}}`, `{{bottomPos}}`, `{{captureChar}}`, `{{captureUser}}`, `{{chainHistory}}`.

Команды: `/sp-chain [block=Имя] [id]`, `/sp-chain-stop`, `/sp-chain-clear [id]`, `/sp-chain-undo [id]`. В меню сообщения есть кнопка-цепочка (Shift+клик убирает блоки).
